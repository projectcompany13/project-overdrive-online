# PROJECT: OVERDRIVE ONLINE

Браузерный 2D arena shooter с комнатами на 2–10 игроков. Клиент использует HTML5 Canvas, сервер — Node.js, Express и Socket.IO.

## Требования
- Windows 10/11
- Node.js 18 или новее (LTS рекомендуется)
- Современный браузер (Chrome, Edge, Firefox)

## Запуск на Windows
1. Распакуй ZIP-архив в отдельную папку.
2. Открой эту папку в Проводнике.
3. В адресной строке Проводника введи `cmd` и нажми Enter (или открой терминал в этой папке).
4. Выполни:

   ```bash
   npm install
   npm start
   ```

5. Открой браузер по адресу **http://localhost:3000**.
6. Нажми «Создать комнату». Отправь друзьям шестизначный код.
7. Друзья, подключённые к тому же серверу, вводят код в поле «Присоединиться».
8. Ведущий нажимает «Начать матч».

Остановить сервер: `Ctrl+C` в окне терминала.

## Управление
- **WASD** или стрелки — движение.
- **Мышь** — направление прицела.
- **ЛКМ** или пробел — стрельба.
- **Shift** — рывок.
- **Q** — импульсная способность (перезарядка 5 секунд).
- **Esc** — открыть меню паузы клиента. Серверный матч при этом не останавливается.

## Игра через интернет
`localhost` доступен только на компьютере, где запущен сервер. Чтобы друзья из других городов подключились:

1. Размести папку проекта на Node.js-хостинге, поддерживающем WebSocket/Socket.IO (например, Render, Railway или VPS).
2. Укажи команду сборки/установки `npm install` и команду запуска `npm start`.
3. Убедись, что хостинг задаёт переменную `PORT` (сервер её использует) и разрешает WebSocket-соединения.
4. После публикации отправь друзьям публичный HTTPS-адрес приложения. Они открывают его и вводят код комнаты.

Для VPS можно запустить Node.js-процесс через `pm2` и настроить HTTPS reverse proxy (например, Nginx + Let's Encrypt). Не публикуй порт напрямую без понимания настроек firewall.

**Важно:** проект в этом архиве не размещён на публичном хостинге. До публикации друзья из других сетей подключиться не смогут. Для теста в одной локальной Wi-Fi сети можно открыть порт 3000 в брандмауэре Windows и дать друзьям локальный IP компьютера с сервером.

## Структура

```text
PROJECT_OVERDRIVE_ONLINE/
├── server.js              # комнаты, игровой цикл и авторитетная симуляция
├── package.json
├── README.md
└── public/
    ├── index.html         # меню, лобби, HUD, экраны матча
    ├── style.css          # интерфейс и неоновая тема
    └── game.js            # Canvas-рендеринг, управление, Socket.IO-клиент
```

## Что рассчитывает сервер
- создание комнат и уникальные коды;
- лимит 10 игроков, вступление/выход и передачу ведущего;
- движение, рывки, перезарядку, стрельбу и снаряды;
- попадания, урон, броню, здоровье, смерть и убийства;
- противников и босса, прогресс раундов;
- персональный набор из трёх случайных улучшений и проверку выбора;
- итоговую таблицу результатов.

Клиент отправляет только ввод игрока. Позиции, здоровье, снаряды и результаты вычисляются сервером и рассылаются клиентам.

## Проверка проекта
- `node --check server.js` и `node --check public/game.js` — проверка синтаксиса.
- `npm test` — автономный smoke-тест логики комнат: создание, вход второго клиента, старт матча, авторитетные снаряды/состояние и выход игрока. Для него не требуется подключение к сети.
- После `npm start` открой `http://localhost:3000/health`. Сервер вернёт JSON со статусом и количеством активных комнат.

Примечание: smoke-тест использует тестовые заглушки Socket.IO/Express; полноценный сетевой прогон двух браузеров нужно выполнить после `npm install` на компьютере или опубликованном сервере.

## Известные ограничения прототипа
- Игровая симуляция рассчитана на небольшие приватные матчи и не включает постоянную базу аккаунтов.
- В текущей версии PvE-волны общие для комнаты; очки и убийства индивидуальные.
- При выходе из комнаты игрок удаляется; при выходе ведущего ведущим становится следующий участник.
- Пауза действует только на локальный интерфейс, чтобы один клиент не останавливал матч для остальных.
- Это готовая основа для развития, но не production-сервис: перед открытым публичным запуском стоит добавить rate limiting, защиту от спама событий, журналирование и нагрузочное тестирование.
